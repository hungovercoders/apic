One static binary · MIT · signed releases

apic is epic

Run API requests from plain .http files, in the terminal, in CI, or from an AI agent, on any platform. The files stay ordinary .http files that VS Code, JetBrains and Neovim already send with one click: everything apic adds is a comment.

Get started Take the course GitHub
$ brew install hungovercoders/tap/apic && apic ui --demo

No account, no API key, nothing to clone. --demo serves a fake API in-process and quits clean.

{# ------------------------------------------------------ three audiences #}

One file, three audiences

The same request, from wherever you are

Write a request once. apic runs it for the person at the keyboard, the pipeline on a schedule, and the agent in the loop, with the same runner and the same result.

For humans

A terminal UI that browses the project, sends the request under the cursor, runs a file as a flow and switches environment without leaving the keyboard.

$ apic ui --env staging
# enter: send · f: run file · e: environment · ?: keys
The terminal UI

For CI

Exit codes that mean something, a pass/fail summary per flow, JUnit reports, and --redact so a stored log says what failed without saying the secret.

- uses: hungovercoders/apic/setup-apic@v0
- run: apic run smoke.http --env ci --redact
CI without leaking secrets

For agents

Stable --json per request, list and describe for discovery, errors that say what to do next, and an MCP server that turns every request into a tool.

$ claude mcp add api -- apic mcp
$ apic run whoami --json | jq .response.status
Agents and MCP

{# ------------------------------------------------------------ features #}

Why it's epic

Everything the terminal and agents need, nothing the editor minds

Postman and Bruno are apps. Editor .http files are great until you leave the editor. curl runs anywhere but has no environments, no chaining, no assertions and no output a program can read. apic keeps the format and adds the rest.

Environments that travel http-client.env.json, .env, the shell and --var, with one precedence order you can print with apic env. Tokens that persist Capture a value once with # @capture. The next run, in a new shell or a new agent call, already has it. # @ref login fetches it when it is missing. Assertions and flows Check status, headers, JSON paths, types, lengths and JSON Schema. A file runs in order with a summary and an exit code; # @retry polls until it passes. Auth a text file cannot do AWS SigV4 from your normal credentials with no SDK, OAuth2 with caching and refresh, digest, API key, basic, bearer, or any CLI that prints a token. Gherkin without Cucumber apic test runs .feature files against the same requests with a built-in vocabulary. JUnit and cucumber reports included. Escape hatches both ways apic import scaffolds from OpenAPI, Postman or a curl command. apic curl and apic snippet print the same request for five other languages. Validate, format, lint apic validate reports problems with line, column and a code, annotates pull requests and feeds code scanning. apic fmt --check keeps files canonical. Safe to log Sensitive headers are masked on both sides without asking. --redact masks bodies, values and captures too, and keeps status, timing and pass/fail. Editors stay in the loop A language server for Neovim, Helix and JetBrains, and a VS Code extension: diagnostics as you type, completion, hover, run lenses and formatting.
{# ---------------------------------------------------------------- tour #}

60-second tour

Log in once. Everything after it just works.

Two requests in one file. The first captures a token; the second uses it. Run them in any order and apic tells you what it needs.

api/auth.http
### Log in and keep the token
# @name login
# @assert status == 200
# @capture token = body.$.access_token
POST {{ '{{baseUrl}}' }}/auth/login
Content-Type: application/json

{"user": "{{ '{{user}}' }}", "password": "{{ '{{password}}' }}"}

### Who am I
# @name whoami
# @assert status == 200
# @assert body.$.email endsWith @example.com
GET {{ '{{baseUrl}}' }}/me
Authorization: Bearer {{ '{{token}}' }}
terminal
$ apic run whoami --env dev
error: auth.http:14: missing variable
  {{ '{{token}}' }}: it is captured by request "login";
  run `apic run login` first, or pass --var token=...

$ apic run login --env dev
POST https://dev.example.com/auth/login
200 OK · 87 ms · 412 B
{ "access_token": "eyJ..." }
✓ status == 200
↳ token = eyJ...

$ apic run whoami --env dev
GET https://dev.example.com/me
200 OK · 41 ms · 96 B
{ "email": "alice@example.com" }
✓ status == 200
✓ body.$.email endsWith @example.com

Exit codes are a contract: 0 ok · 1 an assertion or capture failed · 2 usage, parse error or missing variable · 3 network. With --json every error carries a stable code an agent can branch on. CLI reference · Error catalogue
